# Charmlet: competitive review and desktop direction

Reviewed **2026-10-07**. The strongest direction is a quiet coding companion with useful focus sessions, original silicon artwork and freely usable customization. A swinging charm, a free download or a timer alone will not distinguish it: several alternatives already offer those.

This is a product recommendation, not an approved new phase. Charmlet's current release work and the requirement to merge each phase before starting another remain in force.

## What was reviewed

The user's search was for “charms hanging for windows and mac os.” I reviewed eight directly related charm products/sites and three nearby timer/pet products, using their public pages where accessible. No competitor binaries were installed, no checkout was completed and no performance/privacy claim was independently benchmarked.

The direct Google page required a CAPTCHA; the available search result tool supplied the discovery list. The Windows PC's organization blocked Hangly, Book My Luck and Desktamer pages. Those rows use already-returned official search descriptions and are marked **index only**. I did not bypass the blocks. Prices are the amounts displayed during review, not a guarantee of future or regional pricing. Similar names/copy do not establish common ownership.

“Not found” below means not advertised in the reviewed material, not proof that an application lacks it.

## Recommended differentiation

**Positioning proposal: a calm coding companion that makes focused work feel a little more rewarding.**

1. **Specialize in original silicon and coding artwork.** Wafer maps, probe tips, scope waves, generic GPU/CPU boards, memory stacks and friendly debugging characters are more coherent than an enormous unrelated catalogue. Use invented test data and original art.
2. **Make focus part of the charm.** A progress ring around the peg or a restrained cord-color cue can show a session without changing the saved cord length or occupying another panel.
3. **Use optional, explicit coding milestones.** Later, let the user choose a VS Code task whose successful completion earns a small celebration. Do not infer success from arbitrary terminal text or read code/screens in the background. Lucky Dangle already offers script hooks; our opportunity is a thoughtful editor-native workflow.
4. **Make personal artwork easy and free.** A local browser tool could crop/fit PNG/JPEG/WebP and export a validated pack. This is a proposal, not the current import interface.
5. **Keep one pack format across future hosts.** Art obtained from the gallery should work in the editor and the proposed desktop app under its license.

Free alone and a timer alone are not unique. Several alternatives are free, and two direct competitors already advertise timers. The opportunity is the combination of original coding-focused art, useful editor behavior, user control and a consistent portable pack experience.

## Proposed focus-timer scope

This is a concrete recommendation for a future feature, not implemented or approved as a new phase yet.

- Free25/5 and50/10 presets plus custom focus/break durations.
- Start, pause, resume, stop and skip-break controls accessible by keyboard.
- Visible remaining time and a small peg progress ring; the saved cord setting stays unchanged.
- Gentle completion message using the existing encouragement style. Optional sound/notification, off by default; respect reduced-motion settings.
- Store timer state and derive remaining time from its deadline rather than counting animation frames. Define sleep/lock behavior explicitly; never silently count an overnight sleep as completed focus sessions.
- Stop unnecessary display updates when the view is hidden and recover accurately when shown.
- Optional local completed-session count later, with no guilt-based streak requirement.

First verify pause/resume, reload, hidden views, system sleep, clock changes, reduced motion and alert behavior. Do not begin with screen capture, workday AI memory, simulated availability, compulsory break overlays or an account system.

## A standalone Windows/macOS app

**Feasible, with moderate prototype work and a larger release-quality effort.** It needs its own product phase. The artwork, pendulum code, message bank, pack format and much of the UI can be reused; VS Code hosting, persistence and commands need adapters.

| Work | Reason |
|---|---|
| Transparent desktop window with selective click-through | The empty area must let the user's normal applications receive clicks |
| Windows tray / Mac menu-bar controls | Show/hide, choose charm, timer, settings and quit without another ordinary app window |
| A host adapter | Replace `acquireVsCodeApi`, VS Code storage/dialogs and theme variables while sharing the core |
| Monitor/DPI/Spaces/fullscreen behavior | Keep the charm reachable after monitor changes and avoid unwanted presentation interference |
| Sleep/lock and timer lifecycle | A reliable focus tool must handle laptop sleep and wake predictably |
| Packaging, signing, updates and uninstall | A usable release needs trustworthy installation and maintenance on both systems |
| Real resource/accessibility tests | Do not claim zero battery impact, a specific memory budget or perfect click-through without measuring |

**Prototype recommendation: Electron**, because our renderer already uses TypeScript/HTML/SVG/Matter.js and our pack validator uses Node filesystem/buffer/zlib APIs. Electron's documented mouse-event forwarding supports the click-through interaction on Windows/macOS. A smaller system-webview implementation such as Tauri deserves evaluation later, but it would require more backend adaptation and platform testing.

The first desktop prototype should have one charm, existing packs, tray/menu controls, explicit show/hide and no focus stealing. Then add the timer and multi-monitor/lifecycle polish. Avoid a new global shortcut that hijacks normal editor Save or other common shortcuts. Ship Windows and Mac only after their own signed-installation and real-device checks; an editor CI pass is not a desktop-app pass.

Official technical references: [Electron custom window interactions](https://electronjs.org/docs/latest/tutorial/custom-window-interactions), [BrowserWindow](https://electronjs.org/docs/latest/api/browser-window), [signing and macOS notarization](https://electronjs.org/docs/latest/tutorial/code-signing).

## Sequence and paid artwork

Finish the current Phase3 release-readiness work and owner publishing decisions first. My proposed next functional step is the free focus timer, followed by a live website demo/local pack creator and a standalone desktop prototype. This order remains a recommendation for the owner, not a silently approved roadmap change.

The market comparison strengthens the case for charging only for carefully made optional artwork. Some alternatives already include large free libraries, so “more charms” is not enough evidence that a five-charm pack will sell. The earlier approximatelyUS$5 proposal remains unvalidated: trial one strong original collection and gather feedback before committing to many paid packs.

Original cities/nature/semiconductor/AI collections remain viable directions. Marvel/DC/cartoon/NVIDIA-branded commercial packs require the appropriate rights; another site's use of recognizable characters does not grant us those rights.

The [paid-artwork proposal](paid-artwork-plan.md) records hosted checkout/private delivery and the owner decisions. No focus timer, desktop app, paid product or new phase was created by this review.
